# Назначение

Дать единый и проверяемый процесс работы с MCP-серверами, чтобы:

- Vendor-конфиги (`.claude/`, `.cursor/`, `.codex/`) **никогда не расходились**
  между собой и с реестром.
- Каждое изменение проходило через политику данных и ревью Tech Lead.
- Секреты не утекали в git.

# Когда применять

- Подключение нового MCP-сервера.
- Изменение параметров существующего сервера (transport, args, env, scope).
- Удаление сервера из набора команды.
- Апгрейд версии MCP-пакета.

# Порядок работы

## 1. Согласование назначения и риска

Перед тем как трогать файлы — проверить, что сервер вообще проходит политику:

- К какой категории данных он получает доступ (см. раздел 5 [`ai-usage-policy.md`](../../policies/ai-usage-policy.md))?
- Нужен ли `write: yes`? Если да — какие сценарии записи и почему их нельзя
  закрыть read-only сервером?
- Попадает ли сервер в **запрещённые категории** из [`conventions.md`](../../mcp/conventions.md)
  (prod-БД, отправка сообщений, управление инфраструктурой)?

Если хоть один пункт спорный — **остановиться** и согласовать с Tech Lead в PR
до изменения файлов.

## 2. Запись в реестр

Открыть [`.ai/mcp/servers.md`](../../mcp/servers.md) и добавить:

1. Строку в сводную таблицу: `id`, назначение, data scope, write, owner, status.
2. Детальную запись по шаблону существующих:
   - Package, transport.
   - Назначение (1–2 предложения).
   - Data scope.
   - Параметры запуска.
   - Vendor mapping.
   - Риски и митигация.
3. Запись в "Историю изменений" внизу файла.

## 3. Синхронизация vendor-конфигов (одним PR)

Дополнить **все три** файла **одной и той же** записью — имя сервера и
структура параметров должны совпадать.

### Claude Code → `.claude/settings.json`

В блоке `mcpServers` добавить:

```json
"<id>": {
  "command": "npx",
  "args": ["-y", "<package>"],
  "env": { "<VAR>": "${ENV_VAR}" }
}
```

### Cursor → `.cursor/mcp.json`

В блоке `mcpServers` добавить ту же запись (формат идентичен Claude Code).

### Codex CLI → `.codex/config.toml`

Добавить блок:

```toml
[mcp_servers.<id>]
command = "npx"
args = ["-y", "<package>"]
env = { <VAR> = "${ENV_VAR}" }
```

## 4. Секреты

- В vendor-конфигах **только** placeholder `${ENV_VAR}`. Реальные значения
  попадают через `~/.env` разработчика или Credential Manager.
- В `args` секреты **запрещены** — только в `env`.
- В описании сервера в `servers.md` явно указать, какой env-переменной
  пользоваться (например, `GH_PAT`, `MCP_FS_WHITELIST`).

## 5. Документация для команды

- Если env-переменная новая — добавить её в `docs/onboarding/` (или
  расширить [`.ai/skills/engineering/onboarding.md`](onboarding.md)), чтобы
  разработчик знал, как её настроить локально.
- Обновить раздел 8 [`ai-usage-policy.md`](../../policies/ai-usage-policy.md),
  если сервер вводит новую категорию данных, не покрытую существующими
  правилами.

## 6. Проверка (перед коммитом)

Прогнать чеклист консистентности из [`conventions.md`](../../mcp/conventions.md):

- [ ] Запись в `.ai/mcp/servers.md` существует и заполнена полностью.
- [ ] Один и тот же `id` во всех трёх vendor-конфигах.
- [ ] Секреты — только через `${ENV_VAR}`, реальных значений в diff нет.
- [ ] Если `write: yes` — в PR есть обоснование.
- [ ] При новом transport != stdio — указан в `servers.md`.
- [ ] PAT/API-ключи имеют минимально необходимый scope.

## 7. Удаление сервера

При удалении — обратный порядок:

1. Удалить блок из `.claude/settings.json`, `.cursor/mcp.json`,
   `.codex/config.toml`.
2. Удалить детальную запись и строку таблицы из `.ai/mcp/servers.md`,
   добавить запись в "Историю изменений" с причиной.
3. Если сервер использовался в командной работе (например, ссылался из
   skills) — обновить эти ссылки.

# Формат вывода

1) **План**: какой сервер добавляется/меняется/удаляется и почему.
2) **Diff реестра**: новая или изменённая запись в `.ai/mcp/servers.md`.
3) **Diff vendor-конфигов**: три синхронных правки (`.claude` / `.cursor` /
   `.codex`).
4) **Чеклист** из раздела 6 — прокликанный, не пустой.

# Планка качества (самопроверка)

- [ ] Реестр и три vendor-файла изменены **одним PR**.
- [ ] `id` совпадает во всех четырёх местах.
- [ ] Секретов в diff нет; есть `${ENV_VAR}` placeholder'ы.
- [ ] При `write: yes` — обоснование в PR-описании.
- [ ] Запись в "Истории изменений" `servers.md` обновлена.
- [ ] При новой env-переменной — обновлён онбординг.

# Анти-паттерны

- ❌ Менять `.claude/settings.json` или `.cursor/mcp.json` без записи в
  `.ai/mcp/servers.md`. Vendor-конфиг — производный, не источник.
- ❌ Разные имена сервера в разных клиентах ("github" в Cursor, "gh" в Codex).
- ❌ Реальный PAT / API-ключ в vendor-конфиге — даже "временно для проверки".
- ❌ `write: yes` "на всякий случай" без обоснования. Read-only по умолчанию.
- ❌ Подключение MCP-сервера для prod-БД, отправки сообщений или управления
  инфраструктурой без согласования с Tech Lead.
- ❌ Скрыть нового сервера от ревью, добавив только в personal `~/.claude/`
  или `~/.cursor/`. Командные сервера — в репозитории.
