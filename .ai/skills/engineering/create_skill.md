# Назначение
Стандартизировать **создание и правку** skill-файлов так, чтобы агент по `AGENTS.md` и **`.ai/router.md`** выбирал ровно один route и выполнял процесс предсказуемо.

# Обязательное расположение (репозиторий)
- **Все** skills этого репозитория создаются и хранятся **только** внутри общей папки **`.ai/skills/`**, но **по тематическим подпапкам** (один файл = один skill, расширение **`.md`**).
- Перед созданием skill выбрать группу и путь вида **`.ai/skills/<группа>/<имя>.md`**.
- Базовые группы:
  - **`dotnet/`** — .NET, C#, solution, сервисы, тестовые проекты .NET.
  - **`engineering/`** — ревью, архитектурные аудиты, создание/правка skills.
  - **`product/`** — PRD, MVP, Jira, sprint, AC.
  - **`testing/`** — web/e2e/UI testing.
  - **`research/`** — исследования и сравнения.
  - **`writing/`** — статьи и редактура.
- Персональные skills в `~/.cursor/`, `~/.claude/`, `~/codex/` и в подобных папках не заменяют репозиторные: если правило должно быть общим для команды — оно в **`.ai/skills/`**.

# Язык
- Текст skill (**заголовки разделов, назначение, шаги, анти-паттерны, самопроверка, примеры пояснений**) пишется **на русском языке**.
- Исключения без перевода на русский — там, где нужна буквальная форма для инструментов: ключи YAML (`name`, `description`, `triggers`), команды CLI, пути, имена файлов, идентификаторы в коде, устойчивые термины вроде **Deliverable** / **Output Contract**, если они совпадают с контрактом в `router.md`.

# Когда применять
- Пользователь просит **новый skill**, правило процесса или чеклист для агента.
- Нужно зафиксировать триггеры и формат вывода под **Output Contract** в `router.md`.

# Порядок работы
1. **Назначение (описание skill)**  
   - Если в запросе пользователя **уже** ясно сказано, **что будет делать skill** и **в каких случаях** его применять — зафиксировать это как исходное описание и не дублировать вопрос без нужды.  
   - Если назначение **не задано** или сформулировано размыто — **спросить у пользователя**: что skill должен делать и когда агент должен его выбирать (кратко, по делу).  
   - **Не** переходить к подбору имени файла и к черновику skill до принятого формулирования назначения (или явного «достаточно» от пользователя на основе уточняющих ответов).

2. **Имя skill (файл и поле `name`)** — только **после** п.1:  
   - По согласованному назначению предложить **не менее трёх** вариантов **имени файла** в **snake_case** с расширением **`.md`** (например `review_api_contracts.md`, `api_contract_review.md`, `openapi_review_skill.md`) и для каждого варианта — **одну строку пояснения**, чем имя отражает смысл.  
   - В той же реплике явно написать, что пользователь может: **(А)** выбрать один из предложенных вариантов, **(Б)** **ввести своё** имя файла (латиница, **snake_case**, без пробелов, заканчивается на `.md`).  
   - Поле YAML **`name`**: из выбранного имени файла получить идентификатор без `.md`, дефисы вместо подчёркиваний допустимы (как в существующих skills: `create-solution-dotnet10`); если пользователь ввёл имя с ошибками формата — **нормализовать** и показать итог: «файл …, `name`: …».  
   - Пока пользователь **не** выбрал вариант из списка и **не** подтвердил своё введённое имя — не создавать файл и не править роутер.

3. **Метаданные YAML** в начале файла (после выбора имени):  
   - `name`: согласованный идентификатор (латиница, дефисы допустимы).  
   - `description`: что делает skill и **когда** применять — **на русском**, опираться на назначение из п.1.  
   - `triggers`: список ключевых слов и фраз (желательно).

4. **Тело файла** (как у остальных skills в этом репозитории): разделы вроде **Назначение**, **Когда применять**, **Порядок работы**, **Формат вывода**, **Планка качества**, **Анти-паттерны** — по необходимости, без лишнего текста; язык тела — **русский** (см. раздел **«Язык»**). Содержание тела должно соответствовать назначению из п.1.

5. **Роутер**: добавить **ровно одну** строку в таблицу **Skill table** в **`.ai/router.md`** (категория по смыслу итога: product / engineering / testing / research / writing), указав путь с группой: **`.ai/skills/<группа>/<имя>.md`**.

6. **Проверка**: путь к новому файлу начинается с **`.ai/skills/<группа>/`**; в роутере есть ссылка на этот файл.

# Формат вывода
1) **План** (2–6 пунктов): назначение skill, выбранная **группа**, выбранное/введённое **имя файла**, категория в роутере, черновик триггеров.  
2) **Промежуточный шаг** (если назначение или имя ещё не согласованы): вопрос пользователю и/или **список вариантов имён** + приглашение ввести своё имя — до ответа следующий шаг не считать завершённым.  
3) **Результат (Deliverable)**: содержимое **`.ai/skills/<группа>/<имя>.md`** и правка **`.ai/router.md`** (если skill новый).  
4) **Самопроверка**: чеклист из раздела ниже.

# Планка качества (самопроверка)
- [ ] Есть согласованное **назначение** (из запроса или после явного запроса у пользователя).
- [ ] Имя файла выбрано пользователем **из предложенных вариантов** или **введено им** и при необходимости нормализовано под **snake_case** и `.md`.
- [ ] Выбрана тематическая группа skill.
- [ ] Skill лежит в **`.ai/skills/<группа>/`**, не в корне `.ai/skills/`, не в `.cursor/skills/`, не в `.claude/skills/`, не в `.codex/skills/`.
- [ ] В **`.ai/router.md`** добавлена строка таблицы на этот `.md`.
- [ ] Заполнены `description` и при необходимости `triggers`, чтобы skill однозначно выбирался.
- [ ] Описание skill (markdown-часть и по возможности `description`) **на русском**, допустимы оговорённые исключения из раздела **«Язык»**.
- [ ] Формат ответа агента согласован с **Output Contract** в `router.md`, если этот skill его не переопределяет.

# Анти-паттерны
- ❌ Для этого репозитория источник правды — **`.ai/skills/<группа>/`**. Дублирование в другие папки является анти-паттерном.
- ❌ Создавать новый skill в корне **`.ai/skills/`** без тематической подпапки.
- ❌ Создавать файл skill **до** согласования назначения (если оно не было дано изначально) или **до** выбора/ввода имени пользователем.
- ❌ Новый skill без строки в **`.ai/router.md`** (агент при старте не сможет выбрать его по протоколу).
- ❌ Размытое поле `description` без явного сценария «когда использовать».
- ❌ Весь текст skill на английском, если нет явного запроса команды писать иначе.
