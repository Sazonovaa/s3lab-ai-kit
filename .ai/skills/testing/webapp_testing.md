# Purpose
Подготовить **план** ручного или автоматизированного тестирования веб-приложения (Playwright), шаги воспроизведения и критерии «зелёного» прогона.

# When to use
- Нужен сценарий e2e/smoke, проверка формы, регрессия UI.
- Разбор падения Playwright (логи, таймауты, flaky).

# Inputs needed
- URL среды (без прод-секретов в явном виде), роль пользователя, тестовые данные (синтетика).
- Ветка/сборка под тест.

# Procedure
1) Уточнить **критический путь** пользователя под задачу.
2) Составить **порядок шагов** и ожидаемые состояния UI.
3) Для автотестов: предложить **стабильные селекторы** (роли, test-id), избегать хрупких XPath без нужды.
4) Зафиксировать **негативные** кейсы (валидация, 401/403).
5) Дать чеклист **артефактов** при падении: trace, screenshot, HAR (если политика позволяет).

# Output format
1) **Test plan** (bullet steps)
2) **Playwright outline** (describe/it names or pseudo-code) — если уместно
3) **Data fixtures** (анонимизированные)
4) **Failure triage** — типичные причины и что смотреть в логе

# Quality bar (self-check)
- [ ] Шаги атомарны и проверяемы.
- [ ] Нет утечки секретов в примеры URL/заголовков.
- [ ] Указаны стабильные ожидания (не sleep без причины в авто-сценарии).

# Anti-patterns
- ❌ Тестировать продакшен с реальными PII.
- ❌ Полагаться только на скриншот без шагов воспроизведения.
