# Назначение
Настроить или проверить базовую **observability** существующего .NET сервиса: Serilog, HealthCheck, конфигурацию логирования и endpoint состояния.

# Когда применять
- Пользователь просит добавить или проверить Serilog.
- Нужно добавить HealthCheck endpoint.
- Нужно привести logging/health setup сервиса к единому стилю проекта.
- Сервис уже существует, и создавать новый Clean Architecture каркас не нужно.

# Входные данные
1. **Сервис**: имя или путь к сервису. Если не указан и сервисов несколько — спросить.
2. **Api project**: проект слоя Api выбранного сервиса.
3. **Требуемые проверки здоровья**: базовый self-check или конкретные зависимости. Если зависимости не указаны — добавить только базовый self-check.

# Порядок работы
1. Найти `Program.cs`, `appsettings*.json` и файлы DI-регистрации слоя Api.
2. Проверить, какие пакеты Serilog и HealthChecks уже используются в solution.
3. Подключить Serilog как logger хоста по локальному стилю проекта.
4. Добавить или проверить конфигурацию Serilog в `appsettings.json`, не затирая пользовательские настройки.
5. Добавить `AddHealthChecks()` и endpoint health check.
6. Для внешних зависимостей добавлять checks только если dependency уже есть в сервисе или пользователь явно попросил её включить.
7. Не размещать бизнес-логику, проверки доменных правил или вызовы use case в health endpoint.
8. Выполнить сборку solution или проекта после изменений.

# Формат вывода
1) **План**: сервис, Api project, Serilog-настройки, HealthCheck endpoint, зависимости health checks.
2) **Результат (Deliverable)**: изменённые файлы, подключённые пакеты, endpoint health check.
3) **Самопроверка**: чеклист ниже.

# Планка качества (самопроверка)
- [ ] Serilog подключён как host logger, а не как разрозненные ручные логгеры.
- [ ] HealthCheck endpoint не содержит бизнес-логики.
- [ ] Конфигурация не затирает существующие `appsettings*.json`.
- [ ] Checks внешних зависимостей добавлены только при наличии явного основания.
- [ ] Сборка проекта или solution проверена.

# Анти-паттерны
- ❌ Добавлять бизнес-проверки в health endpoint.
- ❌ Создавать новый сервис вместо настройки существующего.
- ❌ Переписывать всю конфигурацию логирования без необходимости.
- ❌ Добавлять checks для БД, брокеров или внешних API, которых нет в сервисе.
