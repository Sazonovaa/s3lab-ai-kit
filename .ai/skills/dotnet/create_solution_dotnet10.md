# Назначение
Создать **бэкенд-решение** на **C# / .NET 10** (`net10.0`) в формате **`.slnx`** (SLNX), без устаревшего **`.sln`**, с проверяемой сборкой.

# Когда применять
- Новое бэкенд-решение, миграция на SLNX, явное упоминание **.NET 10** / **net10.0** / **slnx**.
- Если после создания solution нужен .NET-сервис/проект — делегировать создание в **`.ai/skills/dotnet/create_project_dotnet10_clean_architecture.md`**.

# Имя решения и название проекта (обязательно)
1. **Запросить у пользователя название проекта** — логическое имя сервиса/контекста на латинице; допускается **составное имя через точку** (например `orders.payments`). Не включать в ответ пользователя префикс **`Tiss.`** и суффикс **`.Backend`** — они задаются шаблоном имени решения ниже. Если название уже дано в запросе — использовать его и не дублировать вопрос без необходимости.
2. **Нормализовать название проекта в PascalCase**:
   - каждое слово начинается с большой буквы, остальные буквы маленькие;
   - пробелы, дефисы и подчёркивания внутри одного сегмента убираются: `orders payments` → `OrdersPayments`;
   - если название составное через точку, каждый сегмент приводится к PascalCase отдельно, точки сохраняются: `orders.payments` → `Orders.Payments`;
   - итоговое нормализованное значение использовать как **`<НазваниеПроекта>`**.
3. **Имя решения** (аргумент `-n` у `dotnet new sln`, базовое имя файла **`.slnx`**): строго по шаблону **`Tiss.<НазваниеПроекта>.Backend`**, где **`<НазваниеПроекта>`** — нормализованное значение из п.2.  
   **Примеры:** `billing` → `Tiss.Billing.Backend` → **`Tiss.Billing.Backend.slnx`**; `orders.payments` → `Tiss.Orders.Payments.Backend` → **`Tiss.Orders.Payments.Backend.slnx`**; `orders payments` → `Tiss.OrdersPayments.Backend` → **`Tiss.OrdersPayments.Backend.slnx`**.
4. Этот skill создаёт **solution**. Создание проектов внутри solution выполняется только после отдельного выбора пользователя (см. порядок работы ниже).

# Порядок работы
1. **SDK**: .NET SDK **10.x**; при необходимости закрепить **`global.json`** (`"version": "10.0.xxx"`).
2. Выполнить блок **«Имя решения и название проекта»** выше (запрос названия → нормализация в **PascalCase** → вычислить **`Tiss.<НазваниеПроекта>.Backend`**).
3. **Решение SLNX** (явный формат):

   ```bash
   dotnet new sln -n Tiss.<НазваниеПроекта>.Backend --format slnx
   ```

   Файл: **`Tiss.<НазваниеПроекта>.Backend.slnx`**. Не создавать `.sln` без явного запроса пользователя.

4. **Спросить про проект в решении**:
   - вопрос: «Создать проект/сервис в этом решении или оставить solution пустым?»
   - вариант по умолчанию: **нет, оставить solution пустым без проектов**;
   - если пользователь отвечает «нет», «не нужно», «оставить пустым» или не выбирает явно создание проекта — не создавать проекты и не добавлять их в solution;
   - если пользователь отвечает «да, создать проект/сервис» и это **.NET**-проект — продолжить через skill **`.ai/skills/dotnet/create_project_dotnet10_clean_architecture.md`**.

5. **Делегирование создания .NET-проекта**:
   - не создавать проекты `Api`, `Application`, `Domain`, `Infrastructure`, `Tests` внутри этого skill;
   - передать контекст в skill **`.ai/skills/dotnet/create_project_dotnet10_clean_architecture.md`**: путь к `.slnx`, `<НазваниеПроекта>` из solution, необходимость запросить название сервиса у пользователя;
   - создание слоёв, ссылок между проектами, solution folder и Clean Architecture выполняет skill **`.ai/skills/dotnet/create_project_dotnet10_clean_architecture.md`**.

6. **Проверка пустого solution**: если проекты не создавались, выполнить `dotnet build Tiss.<НазваниеПроекта>.Backend.slnx` только если `dotnet build` поддерживает пустой `.slnx` в текущем SDK; если SDK сообщает, что в solution нет проектов для сборки — зафиксировать это как ожидаемое состояние пустого solution, не как ошибку.

# Формат вывода
1) **План** (2–6 пунктов): каталог, исходное **название проекта**, нормализованное **название проекта в PascalCase**, **имя решения** по шаблону `Tiss.<НазваниеПроекта>.Backend`, выбор пользователя по проектам (пустой solution или делегирование).
2) **Результат (Deliverable)**: созданный `.slnx`; если пользователь выбрал проект — указать, что создание проекта выполняется через **`.ai/skills/dotnet/create_project_dotnet10_clean_architecture.md`**.
3) **Самопроверка**: см. раздел ниже.

# Классический .sln (legacy)
Только по явному запросу пользователя:

```bash
dotnet new sln -n Tiss.<НазваниеПроекта>.Backend --format sln
```

# Анти-паттерны
- Начинать каркас без **названия проекта** или без имени решения по шаблону **`Tiss.<НазваниеПроекта>.Backend`**.
- Использовать введённое название проекта без нормализации в **PascalCase**.
- Выдавать `.sln` вместо `.slnx` без запроса пользователя.
- Создавать проекты внутри solution без явного выбора пользователя.
- По умолчанию создавать проекты: значение по умолчанию — **оставить solution пустым**.
- Самостоятельно создавать Clean Architecture проекты внутри этого skill вместо делегирования в **`.ai/skills/dotnet/create_project_dotnet10_clean_architecture.md`**.
