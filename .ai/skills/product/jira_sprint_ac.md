# Purpose
Разбить работу на **задачи размера спринта** с **AC** и **DoD**, готовые для постановки в Jira (или аналог).

# When to use
- Планирование спринта, декомпозиция эпика.
- Нужно согласовать критерии приёмки с QA/продуктом.

# Inputs needed
- Эпик или цель спринта, дедлайн, состав команды (роли).
- Зависимости и технические ограничения.

# Procedure
1) Разложить цель на **стори** с измеримым результатом.
2) Для каждой стори: **AC** в формате проверяемых буллетов.
3) Добавить **DoD** команды (тесты, документация, feature flag — по политике).
4) Отметить **зависимости** и блокеры.
5) Предложить **порядок** реализации.

# Output format
Для каждой стори:
- **Title**
- **Description** (кратко)
- **Acceptance criteria** (чеклист)
- **DoD** (ссылка на командный шаблон + специфика стори)
- **Estimate hint** (S/M/L или story points — только если пользователь дал шкалу)

Завершить таблицей **Risks / dependencies**.

# Quality bar (self-check)
- [ ] AC не содержат секретов и внутренних URL без необходимости.
- [ ] Каждая стори закрывается одним MR или явно помечена как цепочка.
- [ ] DoD согласован с `.ai/policies/security_sdlc.md` если касается данных.

# Anti-patterns
- ❌ Микро-таски без ценности для пользователя.
- ❌ AC вида «работает хорошо» без критериев.
