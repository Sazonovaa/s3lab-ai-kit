# Реестр MCP-серверов

## Назначение

Единый, vendor-нейтральный список MCP-серверов, разрешённых к использованию в
команде. Каждая запись описывает **что делает сервер, какие данные он видит,
кто владелец и как он называется в каждом из трёх клиентов**.

> Какие AI-инструменты и модели разрешены → [`.ai/policies/ai-usage-policy.md`](../policies/ai-usage-policy.md)
> Как добавить новый MCP-сервер           → [`.ai/skills/engineering/configure_mcp_server.md`](../skills/engineering/configure_mcp_server.md)
> Правила и transport-конвенции           → [`.ai/mcp/conventions.md`](conventions.md)
> Vendor-конфиги (фактические запускалки) → `.claude/settings.json`, `.cursor/mcp.json`, `.codex/config.toml`

---

## Принципы

1. **Единый источник правды** — этот файл. Vendor-конфиги — производные.
2. **Один сервер = одна запись** с одинаковым `id` (kebab-case) во всех клиентах.
3. **Данные** — каждая запись декларирует, что сервер видит (`data scope`) и какие
   ограничения из политики на него распространяются.
4. **Секреты** — никогда не коммитятся в vendor-конфиги. Только `${ENV_VAR}` или
   placeholder; реальные значения — в `.env.local` разработчика.
5. **Read-only по умолчанию** — серверы с правом записи (`write: yes`) требуют
   отдельного обоснования в PR.

## Условные обозначения статуса

| Status | Значение |
|--------|----------|
| ✅ Approved | Сервер одобрен, есть рабочая реализация, vendor-конфиги синхронизированы. |
| 🚧 Planned | Сервер согласован командой, но нет готовой реализации / пакета. Vendor-конфиги **не** заполнены. Запись фиксирует scope и env-контракт для будущей реализации. |
| ⚠️ Limited | Реализация существует, но поддерживает не все три клиента. В записи перечислены поддерживаемые клиенты. |
| 🔴 Deprecated | Сервер выводится из эксплуатации; в vendor-конфигах его удалить в ближайшем PR. |

## Детальные записи

### `filesystem`

- **Package:** `@modelcontextprotocol/server-filesystem`
- **Transport:** stdio
- **Назначение:** дать агенту чтение/запись файлов **за пределами** cwd активной
  сессии, когда это явно нужно (просмотр соседнего репозитория, генерация в
  другую папку). Внутри cwd используются нативные read/edit-инструменты клиента.
- **Data scope:** только локальная файловая система разработчика, путь
  whitelist'ится аргументом запуска.
- **Параметры запуска:** массив абсолютных путей, к которым разрешён доступ.
  По умолчанию пустой — каждый разработчик дописывает свои пути в `.env.local`.
- **Vendor mapping:**
  - Claude Code → `mcpServers.filesystem` в `.claude/settings.json`
  - Cursor → `mcpServers.filesystem` в `.cursor/mcp.json`
  - Codex → `[mcp_servers.filesystem]` в `.codex/config.toml`
- **Риски:** перезапись/удаление файлов за пределами проекта. Хранить
  whitelist путей коротким и проверять при ревью.

### `git`

- **Package:** `@modelcontextprotocol/server-git`
- **Transport:** stdio
- **Назначение:** структурированный доступ к git-истории без вызова `git` через
  shell (нет проблем с экранированием, secret-guard не срабатывает на `log`).
- **Data scope:** содержимое `.git/` текущего репозитория. Не выходит за
  пределы repository root.
- **Параметры запуска:** путь к repository (по умолчанию cwd сессии).
- **Vendor mapping:** имя `git` во всех клиентах.
- **Риски:** низкие, read-only.

### `github`

- **Package:** `@modelcontextprotocol/server-github`
- **Transport:** stdio
- **Назначение:** работа с GitHub Issues / PR / discussions из агента без `gh` CLI
  и без открытия браузера.
- **Data scope:** GitHub API в рамках скоупа PAT. **Минимально необходимый
  скоуп:** `repo` (private), `read:org`. **Не давать** `delete_repo`, `admin:*`.
- **Параметры запуска:** `GITHUB_PERSONAL_ACCESS_TOKEN` через env. Реальный
  токен — в `~/.env` или Windows Credential Manager, **не** в vendor-конфиге.
- **Vendor mapping:** имя `github` во всех клиентах.
- **Риски:** запись в чужие репозитории при широком скоупе PAT; утечка PAT
  в логи vendor'а. Митигация: PAT с минимальным скоупом + ротация раз в 90 дней.

### `sequential-thinking`

- **Package:** `@modelcontextprotocol/server-sequential-thinking`
- **Transport:** stdio
- **Назначение:** структурированный режим "размышления вслух" для задач, где
  агент склонен срезать углы (архитектурные trade-offs, отладка сложных багов).
- **Data scope:** ничего вне сессии. Чистый reasoning-инструмент.
- **Параметры запуска:** отсутствуют.
- **Vendor mapping:** имя `sequential-thinking` во всех клиентах.
- **Риски:** отсутствуют.

### `memory`

- **Package:** `@modelcontextprotocol/server-memory`
- **Transport:** stdio
- **Назначение:** локальная knowledge graph, переживающая между сессиями. Полезно
  для долгих исследований и онбординга, где у разработчика накапливаются заметки.
- **Data scope:** один JSON-файл на машине разработчика
  (`%USERPROFILE%\.tiss-mcp-memory\graph.json` по умолчанию).
- **Параметры запуска:** `MEMORY_FILE_PATH` через env.
- **Vendor mapping:** имя `memory` во всех клиентах.
- **Риски:** разработчик может неосознанно положить в memory PII или секреты.
  Митигация — раздел 5 политики `ai-usage-policy.md` распространяется и сюда.

### `wikijs` (🚧 Planned)

- **Package:** _не определён_. Известных коммьюнити-MCP под WikiJS на момент
  внесения записи команда не выбрала. Возможные пути:
  1. Найти готовый коммьюнити-пакет и провести security-review.
  2. Написать собственный тонкий MCP-обёртку над WikiJS GraphQL API
     (`/graphql`), разместить в `tools/mcp-wikijs/` или отдельном репо.
- **Transport:** stdio (предпочтительно для соответствия остальным).
- **Назначение:** дать агенту искать страницы внутреннего wiki по запросу,
  читать содержимое, а в режиме `write` — создавать и обновлять страницы
  (черновики, описания фичей, ADR). Уменьшает руками-копирование между
  кодом и документацией.
- **Data scope:** WikiJS GraphQL API внутреннего сервера. URL не публичный,
  поэтому **строго** через env (см. ниже). Объём данных, который сервер
  потенциально видит, — **всё содержимое wiki, доступное под токеном**.
  Назначать токен с минимально достаточной группой/правами WikiJS.
- **Параметры запуска (контракт):**
  - `WIKIJS_URL` — корневой URL инстанса (например, `https://wiki.internal/`).
  - `WIKIJS_TOKEN` — API-токен WikiJS с минимально необходимыми правами.
    На WikiJS 2.x создаётся в **Administration → API Access**; в группе токена
    разрешать только нужные мутации (`page:create`, `page:edit`) и запретить
    `user:*`, `group:*`, `system:*`.
- **Vendor mapping:** имя `wikijs` во всех клиентах **после** появления
  реализации. До этого — записи в vendor-конфигах **нет**.
- **Риски и митигация:**
  - **Утечка содержимого wiki в логи AI-клиента.** Сейчас агент возвращает
    выдержки страниц в контексте; они уходят в trace и могут попасть в
    дампы. Митигация: токен и whitelist групп ограничивает, что вообще можно
    прочитать.
  - **Write в неверную страницу/неверный namespace.** При `write: yes` агент
    может создать страницу не там. Митигация: токену давать доступ только к
    выделенному namespace (например, `/ai/scratch/`), и держать там
    "песочницу" до отдельного решения о расширении scope.
  - **Внутренний URL в git.** Поэтому `WIKIJS_URL` — placeholder, как и в
    `ai-usage-policy.md` §5 (WARN на внутренние hostname).
- **Блокеры до перевода в ✅ Approved:**
  - [ ] Выбран или написан MCP-пакет, проверен security-review.
  - [ ] Тест-токен с минимальным scope подтверждён на dev-инстансе WikiJS.
  - [ ] Описаны конкретные scope-правила (какие группы/namespaces).
  - [ ] Обоснование `write: yes` зафиксировано в PR (по
    [`conventions.md`](conventions.md), раздел "Read-only по умолчанию").
  - [ ] Заполнены секции `Package` и `Vendor mapping` выше; vendor-конфиги
    обновлены одним PR.
