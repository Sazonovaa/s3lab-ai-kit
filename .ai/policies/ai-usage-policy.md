# Политика использования AI (TISS AI Usage Policy)

## Назначение

Единые правила для всей команды: какие AI-инструменты разрешены, какие модели
использовать в каких задачах, что нельзя отправлять в промпты, как осуществляется
контроль. Политика распространяется на всех участников команды независимо от роли.

Изменения в этом файле — через MR + ревью Tech Lead, как код.

---

## 1. Одобренные инструменты

| Инструмент | Статус | Основной сценарий |
|------------|--------|-------------------|
| **Cursor** | ✅ Одобрен | Inline-помощь, быстрые правки, .mdc rules |
| **Claude Code** | ✅ Одобрен | Автономные сессии, создание сервисов, ревью |
| **Codex CLI** | ✅ Одобрен | Автономные сессии, генерация по контракту |
| Другие инструменты | ⚠️ Эксперимент | Только с явного согласования Tech Lead |
| Публичные чат-боты (ChatGPT web, Claude.ai web) | 🔴 Ограничен | Только для задач без кода репозитория и без внутренних данных |

> Добавление нового инструмента в команду — через обсуждение и обновление этого файла.

## 2. Одобренные модели

Команда оперирует **классами моделей**, а не конкретными версиями. Класс —
стабильный контракт (он же поле `model` в субагентах); конкретный ID меняется
по мере выхода новых моделей и обновляется **только здесь**, а не в субагентах
или router. Это убирает рассинхрон и устаревшие ID из множества файлов.

### Классы моделей

| Класс | Когда применять | Маппинг компилятора (Claude) | Текущий ориентир по вендорам¹ |
|-------|-----------------|------------------------------|-------------------------------|
| `heavy` | Сложные trade-off, большой контекст (>50 файлов), архитектура, автономная генерация большого объёма | opus | Anthropic Opus / OpenAI Codex (high) |
| `standard` | Стандартная реализация, рефакторинг, ревью, unit-тесты, PRD, декомпозиция | sonnet | Anthropic Sonnet |
| `light` | Короткие диалоги, уточнения, чеклисты, smoke-планы | haiku | Anthropic Haiku / лёгкая OpenAI |

¹ Конкретные ID моделей — параметр окружения команды; обновляются по мере
релизов и **не хардкодятся** в субагентах и `.ai/router.md`.

### Правило выбора класса

```
По умолчанию → standard
Большой контекст (>50 файлов) или сложные trade-offs → heavy
Автономная генерация большого объёма по контракту → heavy (Codex-класс у соответствующего вендора)
Короткий диалог или уточнение → light
```

Поле `model` в субагенте задаёт класс по умолчанию; компилятор
`scripts/ai/build-ai-kit.mjs` разворачивает его в конкретную модель вендора
(`heavy`→opus, `standard`→sonnet, `light`→haiku). Запрос `heavy` без обоснования
в задаче — nit на ревью.

## 5. Запрещённые данные в промптах

Следующие данные **никогда** не должны попадать в промпты, логи и контекст AI-сессий:

### Блокирующие (BLOCK) — отправка запрещена

| Категория | Примеры |
|-----------|---------|
| Секреты и ключи | API keys, JWT signing keys, `AWS_SECRET_*`, PAT токены |
| Connection strings с паролями | `Server=prod;Password=...`, строки с `Pwd=` |
| Private keys | PEM файлы, `.pfx`, `.p12` |
| Production dumps | Дампы БД, экспорты таблиц с реальными данными |

### Предупреждение (WARN) — использовать с осторожностью

| Категория | Правило |
|-----------|---------|
| PII клиентов | Только анонимизированные (`user_123`, не `ivan@example.com`) |
| Внутренние hostname | Не отправлять prod/stage URL если не требуется задачей |
| NDA-данные | Только описание проблемы, не полный текст переписки |

### Как заменить секреты в промпте

```
# Вместо реального значения:
ConnectionString = "Server=prod-db.internal;Password=SuperSecret123"

# Использовать плейсхолдер:
ConnectionString = "Server=<DB_HOST>;Password=<DB_PASSWORD>"
```

## 6. Гео-ограничения (СНГ)

Команда работает в регионах СНГ. Актуальные ограничения:

| Вопрос | Правило |
|--------|---------|
| Регион обработки данных | Все три одобренных инструмента обрабатывают данные вне СНГ (EU/US серверы Anthropic / OpenAI). Это приемлемо для кода репозитория. |
| Персональные данные граждан РФ / KZ | **Не отправлять** в AI-инструменты — 152-ФЗ (РФ), Закон о персональных данных (KZ). |
| Данные платёжных систем | **Не отправлять** — PCI DSS. |
| Внутренние документы с грифом | **Не отправлять** без согласования с юристом. |

> При появлении команд в EU или других регионах — дополнить этот раздел.

## 7. Контроль использования

### Технический контроль (хуки)

Во всех трёх инструментах настроены хуки:

| Хук | Что делает | Где |
|-----|-----------|-----|
| `secret-guard` | Блокирует shell-команды с потенциальными секретами | `scripts/ai/secret-guard.mjs` (Cursor) |
| `crlf-commit-guard` | Проверяет line endings перед `git commit` | `scripts/hooks/crlf-commit-guard.mjs` (Cursor) |
| `sync-submodule-on-start` | Обновляет AI Kit при старте сессии | `scripts/ai/sync-submodule-on-start.mjs` (все клиенты) |

### Организационный контроль

- Изменения в `.ai/**`, `AGENTS.md`, политиках — **через MR + ревью** (зафиксировано в `catalog.md`).
- Добавление нового инструмента или модели — **обновление этого файла** через MR.
- Рекомендованная модель в субагентах — **часть кода**, проходит ревью.
- Инциденты (секрет попал в промпт) — **ротировать ключ немедленно**, зафиксировать по процессу из `security_sdlc.md`.

### Мониторинг (будущее)

Централизованный мониторинг использования запланирован через MCP сервер
(файлы готовы, внедрение — Фаза 3). До внедрения — самоотчётность команды
и PR-чеклист как основной инструмент контроля.

## 8. MCP-серверы

Model Context Protocol (MCP) — стандартный механизм подключения внешних
инструментов к одобренным AI-клиентам. Команда использует **единый реестр**
одобренных серверов: [`.ai/mcp/servers.md`](../mcp/servers.md).

### Правила

| Правило | Описание |
|---------|----------|
| Источник правды | Реестр в `.ai/mcp/servers.md`. Vendor-конфиги (`.claude/settings.json`, `.cursor/mcp.json`, `.codex/config.toml`) — производные. |
| Добавление сервера | Через MR + ревью Tech Lead. Skill: `.ai/skills/engineering/configure_mcp_server.md`. |
| Секреты | Только через `${ENV_VAR}` в vendor-конфигах. Реальные значения — в `~/.env` разработчика или Credential Manager. |
| Write-серверы | По умолчанию все новые серверы — `write: no`. Право записи требует обоснования в PR. |
| Запрещённые категории | Серверы для prod-БД, отправки сообщений от пользователя, управления инфраструктурой — не подключать без согласования Tech Lead. |

### Данные через MCP

Раздел 5 (Запрещённые данные в промптах) **полностью** распространяется на
MCP. Дополнительно:

- **filesystem-сервер** — whitelist путей не должен включать каталоги с
  prod-дампами, бэкапами и `.env` с реальными секретами.
- **github-сервер** — PAT с минимально необходимым scope. Никогда не давать
  `admin:*` или `delete_repo`.
- **memory-сервер** — не записывать в граф PII, секреты, имена клиентов.
  Граф хранится на машине разработчика, но может попасть в дампы/бэкапы.

### Контроль

- Реестр `.ai/mcp/servers.md` ревьюится Tech Lead'ом как любой код в `.ai/**`.
- Конвенции и чеклист консистентности — [`.ai/mcp/conventions.md`](../mcp/conventions.md).
- Версии MCP-пакетов фиксируются в vendor-конфиге; апгрейд — отдельный PR.

## 9. Для тех кто не хочет использовать AI

Использование AI для **Code Review** — командное решение, не личное.
Скилы `code_review_before_push.md` и `code_review_after_mr.md` — обязательны для всей команды.

Использование AI для **реализации** (написание кода, создание сервисов) — рекомендуется,
но не является обязательным. Разработчик вправе писать код без AI-помощи.

Ожидания от команды:
- Знать какие инструменты одобрены и как их настроить.
- Соблюдать правила по данным (раздел 5) независимо от того, используешь AI или нет.
- Не блокировать других участников команды от использования AI.
