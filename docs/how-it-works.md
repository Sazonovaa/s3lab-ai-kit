# How it works

Архитектура связки kit ↔ проект. Полезно, если что-то ведёт себя неожиданно или
вы планируете расширять kit.

## Ключевая идея

s3lab-ai-kit — это **единый источник правды для AI-инструментов**, подключаемый как
git submodule. Проект содержит только тонкие адаптеры и symlinks; всё реальное
содержимое (промпты, правила, команды) живёт в submodule.

Когда вы обновляете kit (`git submodule update --remote`), новые версии промптов
**сразу видны** всем AI-инструментам, потому что они физически читают файлы через
symlinks.

## Три уровня связи проекта с kit

### 1. CLAUDE.md — через `@`-импорт

Claude Code поддерживает синтаксис `@path/to/file.md` в `CLAUDE.md`. Это работает
рекурсивно (до 5 уровней).

В проекте `CLAUDE.md` — 5 строк:

```markdown
# my-service

@.ai-kit/ai/core.md

## This project
@.ai/project-context.md
```

При старте Claude Code это раскрывается в полный контекст: kit core → stack → workflow
→ все conventions → проектная специфика.

### 2. Cursor rules — через symlink на директорию

```
.cursor/rules -> ../.ai-kit/cursor-rules/
```

Cursor рекурсивно сканирует `.cursor/rules/`. Симлинк на директорию — стандартный
паттерн, Cursor читает файлы прозрачно. Каждый `.mdc` файл сам по себе содержит
`@`-импорты на конкретные conventions из kit.

### 3. Codex / AGENTS.md — через Read-инструкции

Codex не поддерживает `@`-импорты, поэтому `AGENTS.md` содержит явные инструкции:
"Прежде чем что-либо делать, прочти `.ai-kit/ai/core.md`". Это работает для любого
агента, понимающего markdown и имеющего инструмент чтения файлов.

## Claude Code subagents — через symlink на директорию

```
.claude/agents -> ../../.ai-kit/ai/agents/
.claude/commands -> ../../.ai-kit/ai/commands/
```

Claude Code сканирует `.claude/agents/*.md` и `.claude/commands/*.md`. Симлинки
работают прозрачно. Когда вы улучшаете промпт `reviewer` в kit и делаете
`git submodule update --remote`, **новый промпт сразу подхватывается** — никакого
копирования.

## Что коммитится в проекте

```
✓ Коммитится:
  CLAUDE.md, AGENTS.md          — адаптеры (5 строк)
  .claude/agents (symlink)      — git хранит как симлинк
  .claude/commands (symlink)
  .claude/settings.json
  .cursor/rules (symlink)
  .ai/project-context.md        — проектная специфика
  .ai/overrides/*               — если есть проектные override'ы
  docs/architecture.md, docs/adr/*
  .github/*, .editorconfig
  .gitmodules                   — pin на конкретный коммит kit

✗ В .gitignore (через sync-ai-kit):
  .claude/auto-memory/          — личные заметки Claude
  *.bak                         — бэкапы от sync-скрипта
  .env*                         — секреты
```

## Жизненный цикл sync-ai-kit

Скрипт идемпотентный — можно запускать сколько угодно раз.

```
1. Проверяет, что .ai-kit подключён как submodule
2. Создаёт CLAUDE.md, AGENTS.md, .ai/project-context.md (только если их нет)
3. Создаёт symlinks: .claude/agents, .claude/commands, .cursor/rules
   (если уже симлинк — проверяет цель; если файл — делает .bak и заменяет на симлинк)
4. Копирует одноразовые шаблоны (CI, ADR, editorconfig) — только если их нет
5. Дописывает строки в .gitignore — идемпотентно (grep -qxF)
```

Что **никогда** не перезаписывается:
- `.ai/project-context.md` — это ваша проектная информация
- `.ai/overrides/*` — ваши переопределения
- Любой одноразовый шаблон, если он уже существует
- `CLAUDE.md`, если уже есть (только warning, если не импортит kit core)

## Версионирование kit

Каждый проект ссылается на конкретный коммит kit через `.gitmodules`. Это
обеспечивает **воспроизводимость**: задача, выполненная агентом сегодня, использовала
*эту* версию правил.

Семвер:
- **MAJOR** — breaking (переименование агентов, удаление правил)
- **MINOR** — новые агенты, команды, правила
- **PATCH** — улучшения существующих промптов

Каждый релиз сопровождается записью в `CHANGELOG.md`.

## Бюджет контекста

Через `@`-импорты в `CLAUDE.md` мы тянем `core.md` + все conventions. Это значит,
что весь kit-контекст оказывается в context window каждой сессии Claude Code.

Целевой бюджет: **весь kit ≤ 6000 токенов**. Поэтому каждый `conventions/*.md`
держим под 300 слов. Если правило не помещается — это сигнал, что нужно
вынести детали в более точечный документ (например, в `docs/adr/`).

Для Cursor бюджет ещё жёстче: правила с `alwaysApply: true` загружаются в
каждый запрос. Поэтому `040-security.mdc` и `050-git.mdc` — короткие сводки,
а полные тексты живут в `ai/conventions/` и подгружаются через `@`.

## Почему именно так, а не иначе

**Почему submodule, а не npm-пакет или git subtree?**
Submodule даёт явный pin на коммит и явное обновление. Никакой магии менеджера пакетов.
Subtree сложнее обновлять. NPM-пакет требовал бы установки Node даже там, где он не нужен.

**Почему symlinks, а не копии файлов?**
Симлинки — это **истинный zero-copy**. Когда вы улучшаете промпт в kit, он сразу
действует во всех проектах после `git submodule update --remote`. С копиями пришлось
бы каждый раз перезаписывать файлы и риск конфликтов.

**Почему один общий `AGENTS.md`, а не отдельные файлы под каждый AI-инструмент?**
Cursor и Codex CLI оба читают `AGENTS.md`. Один файл — меньше расхождений и проще
поддержка.

**Почему `.ai/` в корне, а не `.aikit-project/` или подобное?**
Короткий путь — легче набирать в командной строке и в импортах. Чёткое
разделение: `.ai-kit/` — kit (read-only), `.ai/` — проектная часть (вы редактируете).
